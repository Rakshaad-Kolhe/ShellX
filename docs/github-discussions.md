# GitHub Discussions Guidelines

This document outlines the organization and community guidelines for **ShellX GitHub Discussions**.

---

## Category Architecture

We maintain four primary discussion categories to keep community communication organized:

| Category | Icon | Description |
| :--- | :---: | :--- |
| **General** | 💬 | Open conversations, project announcements, and community feedback. |
| **Ideas** | 💡 | Proposals for future features, architecture RFCs, and design discussions. |
| **Q&A** | ❓ | Questions about building ShellX, UNIX system programming, or POSIX shell internals. |
| **Showcase** | 🙌 | Demos, tutorials, articles, or projects built using or extending ShellX. |

---

## Guidelines for Posting

### 1. General
- Use for broad feedback, introductions, or open-ended discussions about systems programming.
- Keep conversations respectful and aligned with our [Code of Conduct](../CODE_OF_CONDUCT.md).

### 2. Ideas (Requests for Comments - RFC)
- Before creating a major issue or PR for new features (e.g. Job Control, Readline integration), post an **Idea** thread to gather feedback on architecture and interface design.
- Include background, proposed implementation details, and trade-offs.

### 3. Q&A
- Search existing discussions and issue trackers before creating a new Q&A thread.
- When asking a technical question, provide details on your OS, compiler version (`gcc --version`), and steps to reproduce.
- Once a solution is confirmed, mark the correct response as the **Accepted Answer**.

### 4. Showcase
- Share educational blog posts, YouTube walk-throughs, or code forks that build upon ShellX.
